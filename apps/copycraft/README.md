# Copycraft

A clipboard command for macOS. Press **⌃⌥⌘C** and a card opens at the cursor showing what you copied, plus the actions that fit it. The menu bar icon shows that Copycraft is running: a monochrome template that follows the menu bar (light, dark or tinted) and blinks briefly on each new copy. The detected kind (JSON, Rust, Image, a link's host, YouTube, …) shows in its tooltip and its VoiceOver label. The app has no Dock icon.

Part of the [mac-apps](../../README.md) monorepo.

## Features

- **Detection**: JSON, YAML, XML, HTML, Markdown, Rust, Java, Python, URLs, CSV/TSV, plain text and images. JSON and XML get a *Valid* / *Invalid* title. Text that starts with `{` or `[` and is meant as JSON (a quoted key such as `"name":` or `'name':`, or an array that opens with a string) but does not parse is *JSON · Invalid*: it stays as copied (no YAML reading, even when YAML would accept a trailing comma or single quotes), the meta line says where (*Line 4, column 1: trailing comma*) and the well marks that line. `{a: 1}` without quotes, and JSON lines (one object per line), are not taken for broken JSON. A page with `<!DOCTYPE html>` or a root `<html>` is *HTML* (also on one line, where a style such as `color: teal` once made it read as YAML): highlighted and formatted, without the XML check or a Schema chip. Rust and Java whose brackets do not balance (strings, char literals and comments ignored) get a title such as *Java · missing }* or *Rust · unbalanced )*; formatting still runs and adds no brackets. Python is recognised by a score of Python-only hints (`def`/`class …:`, `import`, `from … import`, `elif`, `with open(`, `self`, `None`/`True`/`False`, an indented block after `:`, `print(`, f-strings, `#` comments) with at least one strong hint, so a lone line such as `f = open("demofile.txt")` stays plain text; Ruby, JavaScript, YAML and prose do not qualify. Python is highlighted but not reformatted, and its title flags brackets (*Python · missing )*), a block without an indented body (*Python · expected indent*) and *mixed tabs and spaces*.
- **Format**: pretty-print with syntax highlighting. JSON, YAML, XML, HTML, Markdown, Rust and Java open already formatted. Formatting is built in and runs in the app, with no outside tools: Rust and Java are re-indented by their brackets (strings, char literals and comments ignored, multi-line strings and comments kept as they are), not run through `rustfmt` or any other program. HTML has its own layout, apart from XML: void elements (`<meta>`, `<link>`, `<br>`, `<img>`, `<hr>`, `<input>`, …) do not open a level, the contents of `script`, `style`, `pre` and `textarea` stay exactly as copied, text with inline elements (`<p>Some <em>words</em>.<br>More.</p>`) stays on one line with its spaces, and a left-out end tag (`<li>`, `<p>`, `<td>`) does not make the indentation drift. XML formatting is unchanged.
- **To JSON**: a YAML entry gets a *To JSON* chip: the YAML as pretty JSON, as a view of the entry (Copy and Save take it, saved as `.json`). Anchors and aliases are expanded (`<<` merge keys too), keys such as `1:` or `true:` become strings, dates stay the text they were copied as, and a copy of several documents (`---`) becomes a JSON array. YAML that does not parse gets no chip, and JSON (which is also YAML) never does. The view gets its own sensitivity labels and is masked like the copy.
- **Convert**: flat `key: value` text → JSON (the *Convert* chip). JSON, CSV and TSV have no conversion: JSON opens formatted, a table opens as a table (*Table ▾* shows its grid; Save there writes CSV, also for a TSV or `;` source).
- **Decode**: JWT, Base64, `data:` URIs, percent-encoding.
- **Dataframe** (the table view; there is no *Dataframe* chip: clicking *Table ▾* opens it, *Original* goes back to the text): CSV, TSV or JSON as a table (Polars), with every column (a wide table scrolls sideways). Saving from this view writes CSV of the version shown (UTF-8, comma separated, a header with the real column names, dates as `yyyy-mm-dd`, also for a TSV or `;` source), named *people.csv* after *people.tsv* or *clipboard.csv*; the save panel's *Format* popup (CSV / Parquet) can pick Parquet instead, and switches the name's extension. An export with up to 10 lines of text above its header (a title, a *Definition: …* line) is still a table: those lines are skipped for the table, its labels and its exports, the meta line says *Header on line N*, and the *Original* view shows them as copied above the aligned table. Columns of ISO dates (`2026-03-09`) and datetimes (`2026-03-09T14:05`, also with a space, seconds or a fraction; no time zone) are read as dates and datetimes when every value is one (one other value keeps the column text), so a CSV saved by Copycraft reads back typed. Columns of `dd/mm/yyyy` text (also with `-` or `.`) are read as dates, so a saved CSV has `yyyy-mm-dd` dates and Parquet a date column; a value with a second part over 12 makes it `mm/dd/yyyy`. When every day and month is 12 or less, both orders fit: Copycraft reads them day first and the meta line says *Dates read as dd/mm/yyyy*. When a value only fits month first (its second part is over 12, as in `01/13/2026`), the column is read `mm/dd/yyyy` and the meta line says *Dates read as mm/dd/yyyy*, without a chip to switch. A column with values that only fit day first and others that only fit month first stays text. Numbers stored as text (quoted, or with a decimal comma as in `2,50`) are typed as the table is read, when every value of the column (empty ones aside) converts; a column with one other value stays text. This happens before the original version, without a step or a note (leading zeros, as in `007`, become numbers too). Conversions (CSV → JSON, TSV → CSV) keep the dates as copied. A table of 7 columns or more opens on its column overview: a plain aligned list (not a grid) under the line *20 columns · 192 rows*, with the headings *column*, *type* and *values* and one line per column. The type is *number*, *whole number*, *date*, *datetime*, *text* or *yes/no*. The values sum the column up: numbers as their range (*0.0 – 13.68*), dates first to last (*2026-03-19 – 2026-09-27*), yes/no as counts (*true 12 · false 3*), text as *12 distinct · most common: Utrecht* (cut at 20 characters), a single value as *always 0.0*, and *· 3 empty* when cells are empty. These are worked out for the version shown, in the background. The meta line says *N rows × M columns*. *Show table* shows the grid and *Show columns* the overview, on any table (a narrow one opens on its grid). The 7-column rule only picks the view an entry opens on: after that, the view shown or chosen stays for every version of the entry, also when a step changes how many columns it has. Copy and Save take the table itself in both. Where 3 or more column names share a prefix of 10 characters or more up to a separator (` - `, `: `, ` | `, …), the card shows it as *…* (*… PV1 Generation*), per group; Copy, Save and the conversions keep the real names.
- **Table versions**: the *Table ▾* chip (on every table) has exactly *Remove duplicate rows* (keeps the first), *Remove empty rows and columns* (trims text first), *Choose columns…*, *Sort ascending ›* and *Sort descending ›* (per column; empty cells last, equal values keep their order) and *Open in window*. Undo and redo are ⌘Z / ⇧⌘Z, the version capsule and the command search (*Undo table step*, *Redo table step*). To find rows, type in the Find field. *Choose columns…* opens a column picker over the well: a filter field, a checkbox per column (the shortened name, the real one in its tooltip, the type dimmed), *All* / *None* (on the columns the filter shows; ⌘A is *All*), *Keeping 8 of 20*, and *Apply* (Return) or *Cancel* (Esc). Space ticks the focused checkbox, ↑ ↓ move through the list. *Apply* takes one step, *Kept 8 of 20 columns*, in the table's column order; it is off while no column or every column is kept. The picker shows column names and types only, and closes when the app loses focus, on Wipe, lock, retention and when the entry or version changes. The table is read in the background as soon as the card shows it, so the menu knows its columns. When a date column fits both orders, the Dataframe view asks with a chip, *Dates are mm/dd/yyyy* (and back). Reading the table another way starts its versions over from the original, as its columns can change. A step adds a version to the table's history entry instead of a new entry: the original, then one per step, at most 20. While a table has more than one version, the Dataframe view shows a version capsule in the chip row, left of the history capsule ‹ 1 / 2 › and the same size: undo ↶, the version shown (*v2/3*; click it for the list of versions, the one shown checked) and redo ↷, also on ⌘Z and ⇧⌘Z (unless you are typing a search). The step of the version shown is in the meta line (*· Duplicates removed*). A step taken from an older version drops the versions after it. Steps run on a background thread (the spinner shows when slow; a newer step cancels the one running). In the grid the first column stays in view while you scroll sideways, as a frozen column in a spreadsheet (from two columns up): it scrolls up and down with the rows, is drawn from the grid's own text (so it is blurred, masked and wiped with the well) and is left out for VoiceOver, which reads the grid itself. *Open in window* (under *Choose columns…*) shows the table in its own resizable window, *Table — Copycraft*: a version bar at the top (↶, the version shown with its list, ↷, and the meta line: rows × columns, labels, the step), a column sidebar (names and types; the toolbar's *Columns* button hides it), the grid with its frozen first column (up to 1,000 rows, the meta line says *Showing 1,000 of N rows*) and a toolbar *Table* menu with the two Remove steps and the two Sort submenus. ⌘Z and ⇧⌘Z undo and redo there, ⌘W closes it. The window stays with its entry while you browse the history and follows its versions both ways (a step in the window shows on the card, and back); there is one table window, so opening another table replaces it. It has the card's protection: it opens blurred (or, without blur, hidden behind a hint) and is revealed by a click, and only once the labels are known; it blurs again when it loses focus; sidebar, grid and frozen column are left out for VoiceOver; it is closed and its text wiped on Wipe, Clear history, lock, sleep and retention, when its entry leaves the history and when the chosen file it shows leaves the card. Its grid is not selectable: Copy and Save stay on the card. No new entitlements. The Dataframe view, Copy and Save (CSV, or Parquet) take the version shown; its size and sensitivity labels are the version's own. Content you revealed stays revealed in every view, chip, version and step of the entry (Original, Dataframe, conversions, Show columns/Show table, the picker, undo and redo), also when a step finishes or its labels arrive; another entry, focus loss, Wipe, lock and retention mask it again. Only the steps are kept for every version; the original and the shown table are kept as frames for the entry on the card and those near it, and are worked out again from the copied text when needed. Versions go with their entry (Wipe, Clear history, lock, retention).
- **About**: *About Copycraft* (menu bar and `⋯`) shows the name, the bundle version, a short offline promise, and the GitHub URL as plain selectable text — Copycraft does not open it.
- **Settings**: the menu bar *Settings…* (and the card's `⋯` menu) opens a window for the global hotkey (multi-modifier; Option alone is rejected), the preferred date order (`dd/mm` or `mm/dd` for ambiguous columns), blur on/off for masked content, and *Open at Login* (`SMAppService`, off by default; when macOS needs approval it opens System Settings › Login Items). Stored in the standard user defaults.
- **Schema / Sample**: JSON → Avro schema (`.avsc`), XML → XSD, XSD → sample XML.
- **Images**: *Info* shows format, size and a data URL. *Text* runs OCR and *QR* reads barcode payloads, both with Apple Vision.
- **Image versions**: the *Image ▾* chip (on a copied picture in history and on a dropped or chosen one) has *Resize* ▸ *50%*, *25%*, *Longest side 2048 / 1024 / 512* and *Custom…* (a width, `1200` or `w 1200`, or a height, `h 800`), then *Rotate 90° left / right*, *Flip horizontal / vertical*, *Remove metadata* and *Grayscale*, and *Undo image step* / *Redo image step*; they are in the command search too. Resize keeps the proportions and never makes a picture larger: a size it already fits says "Already that size or smaller" in the meta line and makes no version. The picture is read upright (its EXIF orientation applied) with ImageIO, and every version is a PNG without metadata (no EXIF, GPS or camera data); *Remove metadata* makes such a copy without changing a pixel. Each step is a version of the entry, as for a table: the original, then one per step, at most 20, with the same version capsule (*v2/3*, undo ↶, redo ↷, ⌘Z and ⇧⌘Z) in the picture view and the step in the meta line with the version's size (*PNG  1024×768  0.21 MB  ·  Resized to 1024×768*). Only the steps are kept for every version; a version is worked out from the original by replaying them, on a background thread (the spinner shows when slow; a newer step cancels the one running), and the one shown and the two shown before it are kept as pictures, zeroized when they are dropped and with their entry (Wipe, Clear history, lock, retention). *Info*, *Text* and *QR* read the version shown (scanned once it is there, and kept with it). *Copy* puts the version shown on the pasteboard as PNG data (`public.png`) and into history as a new copy. *Save* has a *Format* popup under the panel: *PNG*, *JPEG — high (0.9)*, *JPEG — medium (0.7)* and *HEIC*, all written upright without metadata, and for the original also the original *as it is* (byte for byte, metadata included), which is picked first; for a step's version the source's format is picked first (JPEG, HEIC, else PNG). Switching it switches the name's one extension. The picture stays revealed through its versions.
- **Links**: when the clipboard (a drop or a history entry) is one `http`/`https` link and nothing else, the card is titled *Link* (*YouTube* for a video) and shows the URL as plain text, selectable; *Copy* copies it. Nothing is fetched: no page title, preview image or thumbnail. *Visit* opens only `http`/`https` links in your default browser (through `NSWorkspace`), with `user:password@` stripped; the browser loads the page, not Copycraft.
- **Copy / Save**: copy the current view back to the clipboard, or save it through a save panel. The file extension follows the content; the suggested name is the chosen or dropped file's name without its own extension (*people.tsv* → *people.csv*), else *clipboard*, with that one extension.
- **Choose file**: show a local text file (up to 8 MB) on the card instead of the clipboard.
- **Drop**: drop one text file or text (up to 8 MB), or one picture (up to 32 MB), on the card to show it the same way. A picture can be an image file from Finder (PNG, JPEG, HEIC, GIF, WebP, TIFF, BMP, … anything macOS can draw), an image dragged from Safari or Preview, or a photo from Photos (a promised file, written to a temporary folder that is deleted once read). It gets the image card with *Info*, *Text* and *QR*, blurred like a copied image, and *Save* writes it in its own format (or PNG, JPEG or HEIC, see *Image versions*). A drop goes into history like a copy, without changing the clipboard. Several files, folders, PDFs and other files are refused. The card stays open while you work in another app, so open it, then drag from Finder, Safari, Preview, Photos or Notes onto it.
- **History**: the last 20 copies and drops (text and images), kept in memory only, and by default forgotten 15 minutes after the last copy (*Keep history 5 / 15 / 60 min after the last copy* or *until cleared* in `⋯`, stored in the user defaults). Whatever that setting, history is always forgotten when the screen locks, the Mac goes to sleep (or its displays do) or you switch to another user. Step through them with the ‹ / › chevrons in the glass capsule at the right of the chip row, which shows where you are (*1 / 5*; 1 is the newest copy, as in the *History* submenu; › *Next* counts up to older copies, ‹ *Previous* counts back down toward 1), with ← / → (or ⌘← / ⌘→, see *Usage*), or use the menu bar *History* submenu. The capsule appears once history holds two copies. Each copy's format is worked out once. Its card, and a picture's scan (info, recognized text, QR payload), are kept with the history entry while it is shown or next to the one shown, so stepping back and forth does not redo them; further away they are zeroized and worked out again when needed, and they never outlive the entry (falling off the end, *Wipe*). A history picture goes back on the pasteboard as data in its own type (JPEG stays JPEG) plus a PNG copy for apps that only paste PNG (TIFF if that conversion fails), never as a temporary file; files an older version left in the temporary folder (`copycraft-history-*`) are removed at launch. Everything Copycraft writes to the pasteboard carries its own type `nl.marcelkoopman.copycraft.self`, so stepping through history is not taken for a new copy; *Copy*, *Format* on a link and a history entry chosen from the menu are recorded as the newest copy when they are written.

## Privacy

- **Offline by design**: Copycraft never goes online. It makes no network connections and has no networking code or libraries of its own, and the signed app has no network entitlement (only `com.apple.security.app-sandbox` and `com.apple.security.files.user-selected.read-write`), so the App Sandbox refuses a connection as well. Text recognition and barcode reading (Apple Vision) and the blur (CoreImage) run on the device. *Visit* hands a link to your browser. CI checks this: `scripts/check_copycraft_offline.sh` fails when Copycraft's dependency tree holds an HTTP, TLS or socket crate (one exception: `socket2`, which polars' tokio runtime always pulls in and Copycraft never uses) or its sources mention `osascript`, and `apps/copycraft/clippy.toml` makes clippy refuse `std::process::Command`, `std::net` and `std::os::unix::net`.
- **No other rights**: besides the sandbox and files you pick, the signed app has no entitlements: no hardened-runtime exceptions (`com.apple.security.cs.*`) and no Apple Events. *Choose file* and *Save* use the native open and save panels in the app itself (`NSOpenPanel`, `NSSavePanel`), never `osascript`. A test pins the entitlements file, and `scripts/sign_app.sh` and the release workflow check the signed app.
- **Masked content**: the card blurs copied content until you click it. The blur is light enough to recognise the shape (lines, indentation, a picture's outline) but keeps text unreadable; pictures get a stronger blur than text, since text in a picture can be large.
- **Sensitivity labels**: the meta line flags **credential**, **PII** and **financial** content. A first layer of Copycraft's own recognizers runs in one linear regex pass with validation afterwards: private-key headers, JWTs, AWS/GitHub/Slack/Stripe/Google/OpenAI/GitLab/npm tokens, IBAN (mod-97), cards (Luhn), email, NL mobile numbers (on one line, not the tail of a decimal such as `10.06`), BSN (elfproef), and labeled or tabular fields such as names and salaries. [leakguard](https://crates.io/crates/leakguard) then looks only for the classes not found yet (URL credentials, Azure/Telegram/Discord tokens, IP and MAC addresses, US SSNs). Both are linear: about 60 ms for a megabyte. Copycraft only labels content. It never rewrites it. Copies from 32 KB up are checked on a background thread: the card opens right away, its meta line says *Checking…* until the labels arrive, and the content cannot be revealed before that (the click beeps). A newer copy cancels a check that is still running.
- **Private copies**: a copy another app marks private with the [nspasteboard.org](http://nspasteboard.org) types (`org.nspasteboard.ConcealedType` from a password manager, `TransientType`, `AutoGeneratedType`) is never recorded in history and its text is not read: the card only says *Hidden content*. When Copycraft itself puts text labelled *credential*, *PII* or *financial* on the pasteboard (*Copy*, a history step), it adds `ConcealedType`, so other clipboard managers skip it, and by default it empties the pasteboard again 60 seconds later if nothing else was copied meanwhile (*Clear sensitive copies after 60 s* in `⋯`, stored in the user defaults).
- **Polling**: macOS has no notification for clipboard changes, so Copycraft looks at the pasteboard's change count every second while the card is closed and every 400 ms while it is open. Only when the count changes is the copy read, hashed and recorded; copying the newest entry again changes nothing in history. Pasteboard privacy (macOS 15.4+, see `docs/pasteboard-privacy/FINDINGS.md`): the access setting (*Privacy & Security › Paste from Other Apps*) picks how copies are read, and is looked at again on every look at a new copy and whenever the card opens, so a change in Settings is picked up while Copycraft runs (and logged). *Allow* (and macOS before 15.4): every copy is read as it comes, as above. *Ask* (or never asked yet): while the card is closed Copycraft only watches the change count and the types (no alert); the menu bar tooltip says *New copy — open the card to view*, and the copy is read when you open the card, in one pass on the main thread that history, the card, the picture and its scan share, so macOS asks at most once per copy. Copies you never open are not read, so they are not in history. The first time, the card first explains the alert (once): choose *Allow* to see the copy, or set Copycraft to *Always Allow* in Settings. *Deny*: Copycraft reads no contents at all (only the change count and the types) and the card says *Clipboard access denied in Privacy & Security*. A reading that comes back empty, fails or is denied is not tried again until another copy or other types, and the pasteboard is only read on the main thread (the image scan decodes on its own thread what was fetched before).
- **Wipe**: the *Wipe* button clears history, caches, the card and the pasteboard. Copied text and image buffers are zeroized when they are dropped (`zeroize`). Beyond that, Copycraft's own allocator overwrites every block of heap memory with zeros before it is freed, so copies that libraries make on the way (Polars' table columns and the CSV reader's chunks, rendered grids, hash tables) do not linger in freed memory either.
- **Masked again on focus loss**: the card stays open (floating) when another app becomes active, but content you revealed is blurred again. It closes with ✕, Esc, the hotkey or a click on the menu bar icon.
- **Out of screen capture**: the card and the table window ask macOS to leave them out of screenshots, screen recordings and screen sharing (`NSWindowSharingNone`). That is a request, not a guarantee: Apple documents the setting as a legacy constant not to be used to hide content from capture ([NSWindow.SharingType.none](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none)), and ScreenCaptureKit on macOS 15.4+ is reported to capture such windows anyway; Apple says there is no public API to prevent screen capture ([Developer Forums 792152](https://developer.apple.com/forums/thread/792152)). The blur stays the protection. For testing, *Allow screenshots* in the menu bar menu (with a checkmark) lets screenshots, recordings and screen sharing capture the card and the table window (read-only sharing) until it is switched off; it is off at every start and never stored. Blur and wipe work the same either way.

## Usage

| Input | Action |
| --- | --- |
| ⌃⌥⌘C | Open the card at the cursor, or close it |
| Click the menu bar icon | Open the card under the icon, or close it |
| Right-click the menu bar icon | Hotkey hint, *History*, version, *Quit* |
| Type any text, or `/` | Search actions, history and appearance |
| ← → | ‹ *Previous* / › *Next* in history (like the chevrons; a beep at 1 or at the oldest). Without history they move the selection. In the search or find field with text they move the caret |
| ⌘← ⌘→ | ‹ *Previous* / › *Next* in history, always, also while typing |
| ↑ ↓, Return | Move the selection (to the row above or below, else the previous or next action), run the selected action |
| ⌘F | Find in the revealed content (case-insensitive). Return / ⇧Return jump to the next / previous match. The counter counts every match; at most 1000 around the current one are highlighted. In content over 200 KB the search runs once typing pauses (150 ms) |
| Esc | Clear the find or search field, then close the card |
| `⋯` | Choose file, Clipboard, Empty pasteboard, history, Clear history, Clear sensitive copies after 60 s (on/off), Keep history 5 / 15 / 60 min or until cleared, Appearance (System / Light / Dark), Quit |

## Build and run

From the repo root:

```bash
cargo run -p copycraft
cargo test -p copycraft
cargo clippy -p copycraft --all-targets -- -D warnings
```

Test data: [`testdata/`](testdata/README.md) has a synthetic input for every scenario
(detection, convert and decode, tables, sensitivity labels, edge cases, images) with a manifest
of what the card should show. `cargo test -p copycraft testdata_manifest` checks the manifest
against the app; `testdata/generate_large.sh` writes the 1 MB and over-8 MB files.

Local app bundle (needs `cargo-bundle`):

```bash
cd apps/copycraft && cargo bundle --release
```

## Release

```bash
scripts/tag_release.sh copycraft
```

This bumps the patch version and tags `copycraft-vX.Y.Z`. GitHub Actions then builds an ad-hoc signed `copycraft-X.Y.Z.dmg` (Apple silicon) and publishes it on [Releases](https://github.com/marcelkoopman/mac-apps/releases). See the [root README](../../README.md#release) for details.
