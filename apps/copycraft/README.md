# Copycraft

A clipboard command for macOS. Press **⌃⌥⌘C** and a card opens at the cursor showing what you copied, plus the actions that fit it. The menu bar icon shows that Copycraft is running: a monochrome template that follows the menu bar (light, dark or tinted) and blinks briefly on each new copy. The detected kind (JSON, Rust, Image, a link's host, YouTube, …) shows in its tooltip and its VoiceOver label. The app has no Dock icon.

Part of the [mac-apps](../../README.md) monorepo.

## Features

- **Detection**: JSON, YAML, XML, HTML, Markdown, Rust, Java, Python, URLs, CSV/TSV, plain text and images. JSON and XML get a *Valid* / *Invalid* title. A page with `<!DOCTYPE html>` or a root `<html>` is *HTML*: highlighted and formatted like XML, without the XML check or a Schema chip. Rust and Java whose brackets do not balance (strings, char literals and comments ignored) get a title such as *Java · missing }* or *Rust · unbalanced )*; formatting still runs and adds no brackets. Python is recognised by a score of Python-only hints (`def`/`class …:`, `import`, `from … import`, `elif`, `with open(`, `self`, `None`/`True`/`False`, an indented block after `:`, `print(`, f-strings, `#` comments) with at least one strong hint, so a lone line such as `f = open("demofile.txt")` stays plain text; Ruby, JavaScript, YAML and prose do not qualify. Python is highlighted but not reformatted, and its title flags brackets (*Python · missing )*), a block without an indented body (*Python · expected indent*) and *mixed tabs and spaces*.
- **Format**: pretty-print with syntax highlighting. JSON, YAML, XML, HTML, Markdown, Rust and Java open already formatted. Formatting is built in and runs in the app, with no outside tools: Rust and Java are re-indented by their brackets (strings, char literals and comments ignored, multi-line strings and comments kept as they are), not run through `rustfmt` or any other program.
- **Convert**: JSON ↔ YAML, CSV → JSON, TSV → CSV, flat `key: value` text → JSON.
- **Decode**: JWT, Base64, `data:` URIs, percent-encoding.
- **Dataframe**: CSV, TSV or JSON as a table (Polars), with every column (a wide table scrolls sideways). Saving from this view writes CSV of the version shown (UTF-8, comma separated, a header with the real column names, dates as `yyyy-mm-dd`, also for a TSV or `;` source), named *people.csv* after *people.tsv* or *clipboard.csv*; the save panel's *Format* popup (CSV / Parquet) can pick Parquet instead, and switches the name's extension. An export with up to 10 lines of text above its header (a title, a *Definition: …* line) is still a table: those lines are skipped for the table, its labels and its exports, the meta line says *Header on line N*, and the *Original* view shows them as copied above the aligned table. Columns of `dd/mm/yyyy` text (also with `-` or `.`) are read as dates, so a saved CSV has `yyyy-mm-dd` dates and Parquet a date column; a value with a second part over 12 makes it `mm/dd/yyyy`. When every day and month is 12 or less, both orders fit: Copycraft reads them day first and the meta line says *Dates read as dd/mm/yyyy*. Conversions (CSV → JSON, TSV → CSV) keep the dates as copied. A table of 7 columns or more opens on its column overview: a plain aligned list (not a grid) under the line *20 columns · 192 rows*, with the headings *column*, *type* and *values* and one line per column. The type is *number*, *whole number*, *date*, *datetime*, *text* or *yes/no*. The values sum the column up: numbers as their range (*0.0 – 13.68*), dates first to last (*2026-03-19 – 2026-09-27*), yes/no as counts (*true 12 · false 3*), text as *12 distinct · most common: Utrecht* (cut at 20 characters), a single value as *always 0.0*, and *· 3 empty* when cells are empty. These are worked out for the version shown, in the background. The meta line says *N rows × M columns*. *Show table* shows the grid and *Show columns* the overview, on any table (a narrow one opens on its grid). The 7-column rule only picks the view an entry opens on: after that, the view shown or chosen stays for every version of the entry, also when a step changes how many columns it has. Copy and Save take the table itself in both. Where 3 or more column names share a prefix of 10 characters or more up to a separator (` - `, `: `, ` | `, …), the card shows it as *…* (*… PV1 Generation*), per group; Copy, Save and the conversions keep the real names.
- **Table versions**: the *Table ▾* chip (on every table) has *Describe*, the steps, *Undo table step* and *Redo table step*; they are in the command search too. *Describe* is a view of the version shown, not a version: one row per column with its type, count, empty cells, distinct values, min, max and (numbers) mean; *Back to the table* leaves it. The steps: *Remove duplicate rows* (keeps the first), *Remove empty rows and columns* (trims text first), *Remove constant columns* (one value in every row), *Fix types* (a text column becomes numbers, also with a decimal comma, or dates, `yyyy-mm-dd` or day-first `dd/mm/yyyy`, only when every value converts; when no column changes, as when the table was read with its numbers and dates typed already, the meta line says "Types already fine" and no version is made) and *Transpose* (at most 200 rows; the first column names the new columns when its values are all there and different, every value becomes text). Per column, in submenus: *Sort ascending* and *Sort descending* (empty cells last, equal values keep their order), *Value counts* (each value once with its number of rows, the most common first), *Remove column* and *Move column to front* (at least one column stays). *Choose columns…* opens a column picker over the well: a filter field, a checkbox per column (the shortened name, the real one in its tooltip, the type dimmed), *All* / *None* (on the columns the filter shows; ⌘A is *All*), *Keeping 8 of 20*, and *Apply* (Return) or *Cancel* (Esc). Space ticks the focused checkbox, ↑ ↓ move through the list. *Apply* takes one step, *Kept 8 of 20 columns*, in the table's column order; it is off while no column or every column is kept. The picker shows column names and types only, and closes when the app loses focus, on Wipe, lock, retention and when the entry or version changes. The table is read in the background as soon as the card shows it, so the menu knows its columns. *Header on line* ▸ *Line N* reads the table from another line when the header was guessed wrong. When a date column fits both orders, the Dataframe view asks with a chip, *Dates are mm/dd/yyyy* (and back); it is in the menu too. Reading the table another way starts its versions over from the original, as its columns can change. A step adds a version to the table's history entry instead of a new entry: the original, then one per step, at most 20. While a table has more than one version, the Dataframe view shows a version capsule in the chip row, left of the history capsule ‹ 1 / 2 › and the same size: undo ↶, the version shown (*v2/3*; click it for the list of versions, the one shown checked) and redo ↷, also on ⌘Z and ⇧⌘Z (unless you are typing a search). The step of the version shown is in the meta line (*· Duplicates removed*). A step taken from an older version drops the versions after it. Steps run on a background thread (the spinner shows when slow; a newer step cancels the one running). The Dataframe view, Copy and Save (CSV, or Parquet) take the version shown; its size and sensitivity labels are the version's own. Content you revealed stays revealed in every view, chip, version and step of the entry (Original, Dataframe, conversions, Describe, Show columns/Show table, the picker, undo and redo), also when a step finishes or its labels arrive; another entry, focus loss, Wipe, lock and retention mask it again. Only the steps are kept for every version; the original and the shown table are kept as frames for the entry on the card and those near it, and are worked out again from the copied text when needed. Versions go with their entry (Wipe, Clear history, lock, retention).
- **Schema / Sample**: JSON → Avro schema (`.avsc`), XML → XSD, XSD → sample XML.
- **Images**: *Info* shows format, size and a data URL. *Text* runs OCR and *QR* reads barcode payloads, both with Apple Vision.
- **Links**: when the clipboard (a drop or a history entry) is one `http`/`https` link and nothing else, the card is titled *Link* (*YouTube* for a video) and shows the URL as plain text, selectable; *Copy* copies it. Nothing is fetched: no page title, preview image or thumbnail. *Visit* opens only `http`/`https` links in your default browser (through `NSWorkspace`), with `user:password@` stripped; the browser loads the page, not Copycraft.
- **Copy / Save**: copy the current view back to the clipboard, or save it through a save panel. The file extension follows the content; the suggested name is the chosen or dropped file's name without its own extension (*people.tsv* → *people.csv*), else *clipboard*, with that one extension.
- **Choose file**: show a local text file (up to 8 MB) on the card instead of the clipboard.
- **Drop**: drop one text file or text (up to 8 MB), or one picture (up to 32 MB), on the card to show it the same way. A picture can be an image file from Finder (PNG, JPEG, HEIC, GIF, WebP, TIFF, BMP, … anything macOS can draw), an image dragged from Safari or Preview, or a photo from Photos (a promised file, written to a temporary folder that is deleted once read). It gets the image card with *Info*, *Text* and *QR*, blurred like a copied image, and *Save* writes it in its own format. A drop goes into history like a copy, without changing the clipboard. Several files, folders, PDFs and other files are refused. The card stays open while you work in another app, so open it, then drag from Finder, Safari, Preview, Photos or Notes onto it.
- **History**: the last 20 copies and drops (text and images), kept in memory only, and by default forgotten 15 minutes after the last copy (*Keep history 5 / 15 / 60 min after the last copy* or *until cleared* in `⋯`, stored in the user defaults). Whatever that setting, history is always forgotten when the screen locks, the Mac goes to sleep (or its displays do) or you switch to another user. Step through them with the ‹ / › chevrons in the glass capsule at the right of the chip row, which shows where you are (*1 / 5*; 1 is the newest copy, as in the *History* submenu; › *Next* counts up to older copies, ‹ *Previous* counts back down toward 1), with ← / → (or ⌘← / ⌘→, see *Usage*), or use the menu bar *History* submenu. The capsule appears once history holds two copies. Each copy's format is worked out once. Its card, and a picture's scan (info, recognized text, QR payload), are kept with the history entry while it is shown or next to the one shown, so stepping back and forth does not redo them; further away they are zeroized and worked out again when needed, and they never outlive the entry (falling off the end, *Wipe*). A history picture goes back on the pasteboard as data in its own type (JPEG stays JPEG) plus a PNG copy for apps that only paste PNG (TIFF if that conversion fails), never as a temporary file; files an older version left in the temporary folder (`copycraft-history-*`) are removed at launch. Everything Copycraft writes to the pasteboard carries its own type `nl.marcelkoopman.copycraft.self`, so stepping through history is not taken for a new copy; *Copy*, *Format* on a link and a history entry chosen from the menu are recorded as the newest copy when they are written.

## Privacy

- **Offline by design**: Copycraft never goes online. It makes no network connections and has no networking code or libraries of its own, and the signed app has no network entitlement (only `com.apple.security.app-sandbox` and `com.apple.security.files.user-selected.read-write`), so the App Sandbox refuses a connection as well. Text recognition and barcode reading (Apple Vision) and the blur (CoreImage) run on the device. *Visit* hands a link to your browser. CI checks this: `scripts/check_copycraft_offline.sh` fails when Copycraft's dependency tree holds an HTTP, TLS or socket crate (one exception: `socket2`, which polars' tokio runtime always pulls in and Copycraft never uses) or its sources mention `osascript`, and `apps/copycraft/clippy.toml` makes clippy refuse `std::process::Command`, `std::net` and `std::os::unix::net`.
- **No other rights**: besides the sandbox and files you pick, the signed app has no entitlements: no hardened-runtime exceptions (`com.apple.security.cs.*`) and no Apple Events. *Choose file* and *Save* use the native open and save panels in the app itself (`NSOpenPanel`, `NSSavePanel`), never `osascript`. A test pins the entitlements file, and `scripts/sign_app.sh` and the release workflow check the signed app.
- **Masked content**: the card blurs copied content until you click it. The blur is light enough to recognise the shape (lines, indentation, a picture's outline) but keeps text unreadable; pictures get a stronger blur than text, since text in a picture can be large.
- **Sensitivity labels**: the meta line flags **credential**, **PII** and **financial** content. A first layer of Copycraft's own recognizers runs in one linear regex pass with validation afterwards: private-key headers, JWTs, AWS/GitHub/Slack/Stripe/Google/OpenAI/GitLab/npm tokens, IBAN (mod-97), cards (Luhn), email, NL mobile numbers (on one line, not the tail of a decimal such as `10.06`), BSN (elfproef), and labeled or tabular fields such as names and salaries. [leakguard](https://crates.io/crates/leakguard) then looks only for the classes not found yet (URL credentials, Azure/Telegram/Discord tokens, IP and MAC addresses, US SSNs). Both are linear: about 60 ms for a megabyte. Copycraft only labels content. It never rewrites it. Copies from 32 KB up are checked on a background thread: the card opens right away, its meta line says *Checking…* until the labels arrive, and the content cannot be revealed before that (the click beeps). A newer copy cancels a check that is still running.
- **Private copies**: a copy another app marks private with the [nspasteboard.org](http://nspasteboard.org) types (`org.nspasteboard.ConcealedType` from a password manager, `TransientType`, `AutoGeneratedType`) is never recorded in history and its text is not read: the card only says *Hidden content*. When Copycraft itself puts text labelled *credential*, *PII* or *financial* on the pasteboard (*Copy*, a history step), it adds `ConcealedType`, so other clipboard managers skip it, and by default it empties the pasteboard again 60 seconds later if nothing else was copied meanwhile (*Clear sensitive copies after 60 s* in `⋯`, stored in the user defaults).
- **Polling**: macOS has no notification for clipboard changes, so Copycraft looks at the pasteboard's change count every second while the card is closed and every 400 ms while it is open. Only when the count changes is the copy read, hashed and recorded; copying the newest entry again changes nothing in history.
- **Wipe**: the *Wipe* button clears history, caches, the card and the pasteboard. Copied text and image buffers are zeroized when they are dropped (`zeroize`). Beyond that, Copycraft's own allocator overwrites every block of heap memory with zeros before it is freed, so copies that libraries make on the way (Polars' table columns and the CSV reader's chunks, rendered grids, hash tables) do not linger in freed memory either.
- **Masked again on focus loss**: the card stays open (floating) when another app becomes active, but content you revealed is blurred again. It closes with ✕, Esc, the hotkey or a click on the menu bar icon.

## Usage

| Input | Action |
| --- | --- |
| ⌃⌥⌘C | Open the card at the cursor, or close it |
| Click the menu bar icon | Open the card under the icon, or close it |
| Right-click the menu bar icon | Hotkey hint, *History*, version, *Quit* |
| Type any text, or `/` | Search actions, history and appearance |
| ← → | ‹ *Previous* / › *Next* in history (like the chevrons; a beep at 1 or at the oldest). Without history they move the selection. In the search or find field with text they move the caret |
| ⌘← ⌘→ | ‹ *Previous* / › *Next* in history, always, also while typing |
| ↑ ↓, Return | Move the selection (to the row above or below, else the previous or next action), run the selected action |
| ⌘F | Find in the revealed content (case-insensitive). Return / ⇧Return jump to the next / previous match. The counter counts every match; at most 1000 around the current one are highlighted. In content over 200 KB the search runs once typing pauses (150 ms) |
| Esc | Clear the find or search field, then close the card |
| `⋯` | Choose file, Clipboard, Empty pasteboard, history, Clear history, Clear sensitive copies after 60 s (on/off), Keep history 5 / 15 / 60 min or until cleared, Appearance (System / Light / Dark), Quit |

## Build and run

From the repo root:

```bash
cargo run -p copycraft
cargo test -p copycraft
cargo clippy -p copycraft --all-targets -- -D warnings
```

Local app bundle (needs `cargo-bundle`):

```bash
cd apps/copycraft && cargo bundle --release
```

## Release

```bash
scripts/tag_release.sh copycraft
```

This bumps the patch version and tags `copycraft-vX.Y.Z`. GitHub Actions then builds an ad-hoc signed `copycraft-X.Y.Z.dmg` (Apple silicon) and publishes it on [Releases](https://github.com/marcelkoopman/mac-apps/releases). See the [root README](../../README.md#release) for details.
