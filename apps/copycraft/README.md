# Copycraft

A clipboard command for macOS. Press **⌃⌘C** and a card opens at the cursor showing what you copied, plus the actions that fit it. The menu bar icon shows that Copycraft is running: a monochrome template that follows the menu bar (light, dark or tinted) and blinks briefly on each new copy. The detected kind (JSON, Rust, Image, a link's host, YouTube, …) shows in its tooltip and its VoiceOver label. The app has no Dock icon.

Part of the [mac-apps](../../README.md) monorepo.

## Features

- **Detection**: JSON, YAML, XML, HTML, Markdown, Rust, Java, Python, URLs, CSV/TSV, plain text and images. JSON and XML get a *Valid* / *Invalid* title. Text that starts with `{` or `[` and is meant as JSON (a quoted key such as `"name":` or `'name':`, or an array that opens with a string) but does not parse is *JSON · Invalid*: it stays as copied (no YAML reading, even when YAML would accept a trailing comma or single quotes), the meta line says where (*Line 4, column 1: trailing comma*) and the well marks that line. `{a: 1}` without quotes, and JSON lines (one object per line), are not taken for broken JSON. A page with `<!DOCTYPE html>` or a root `<html>` is *HTML* (also on one line, where a style such as `color: teal` once made it read as YAML): highlighted and formatted, without the XML check or a Schema chip. Rust and Java whose brackets do not balance (strings, char literals and comments ignored) get a title such as *Java · missing }* or *Rust · unbalanced )*; formatting still runs and adds no brackets. Python is recognised by a score of Python-only hints (`def`/`class …:`, `import`, `from … import`, `elif`, `with open(`, `self`, `None`/`True`/`False`, an indented block after `:`, `print(`, f-strings, `#` comments) with at least one strong hint, so a lone line such as `f = open("demofile.txt")` stays plain text; Ruby, JavaScript, YAML and prose do not qualify. Python is highlighted but not reformatted, and its title flags brackets (*Python · missing )*), a block without an indented body (*Python · expected indent*) and *mixed tabs and spaces*.
- **Format**: pretty-print with syntax highlighting. JSON, YAML, XML, HTML, Markdown, Rust and Java open already formatted. Formatting is built in and runs in the app, with no outside tools: Rust and Java are re-indented by their brackets (strings, char literals and comments ignored, multi-line strings and comments kept as they are), not run through `rustfmt` or any other program. HTML has its own layout, apart from XML: void elements (`<meta>`, `<link>`, `<br>`, `<img>`, `<hr>`, `<input>`, …) do not open a level, the contents of `script`, `style`, `pre` and `textarea` stay exactly as copied, text with inline elements (`<p>Some <em>words</em>.<br>More.</p>`) stays on one line with its spaces, and a left-out end tag (`<li>`, `<p>`, `<td>`) does not make the indentation drift. XML formatting is unchanged.
- **To JSON**: a YAML entry gets a *To JSON* chip: the YAML as pretty JSON, as a view of the entry (Copy and Save take it, saved as `.json`). Anchors and aliases are expanded (`<<` merge keys too), keys such as `1:` or `true:` become strings, dates stay the text they were copied as, and a copy of several documents (`---`) becomes a JSON array. YAML that does not parse gets no chip, and JSON (which is also YAML) never does. The view gets its own sensitivity labels and is masked like the copy.
- **Convert**: flat `key: value` text → JSON (the *Convert* chip). JSON, CSV and TSV have no conversion: JSON opens formatted, and a CSV or TSV stays the copied text on the card. *Open table* opens its grid; Save there writes CSV with the source's separator.
- **Decoders**: one chip next to *Raw*, titled with what the copy decodes as (*JWT*, *UUID*, *Unix time* / *Unix-tijd*, *URL*, *Hash*, *Base64*), shows the decoded text read-only; *Raw* goes back. See [Decoders](#decoders).
- **Table**: a CSV or TSV opens on the card as the copied text, aligned and colored as that table. The only chip is *Open table* (it opens a window). There is no *Dataframe* chip, no *Table ▾* chip and no *Show columns* / *Show table* chip. JSON opens formatted (with *Schema* when it parses) and is not offered as a table. *Open table* closes the card and opens the grid in its own window (see *Table versions*). Saving from that window writes CSV of the version shown (UTF-8, the source's separator (comma, `;` or tab), a header with the real column names, dates as `yyyy-mm-dd`, quoted where needed), named *people.csv* after *people.tsv* or *clipboard.csv*; the save panel's *Format* popup (CSV / Parquet) can pick Parquet instead, and switches the name's extension. An export with up to 10 lines of text above its header (a title, a *Definition: …* line) is still a table: those lines are skipped for the table, its labels and its exports, the meta line says *Header on line N*, and the card shows them as copied above the aligned table. Columns of ISO dates (`2026-03-09`) and datetimes (`2026-03-09T14:05`, also with a space, seconds or a fraction; no time zone) are read as dates and datetimes when every value is one (one other value keeps the column text), so a CSV saved from the table reads back typed. Columns of `dd/mm/yyyy` text (also with `-` or `.`) are read as dates, so a saved CSV has `yyyy-mm-dd` dates and Parquet a date column; a value with a second part over 12 makes it `mm/dd/yyyy`. When every day and month is 12 or less, both orders fit: a new table starts from Settings › Date order (day first unless you chose `mm/dd`) and the meta line says *Dates read as dd/mm/yyyy* or *Dates read as mm/dd/yyyy*. When a value only fits month first (its second part is over 12, as in `01/13/2026`), the column is read `mm/dd/yyyy` and the meta line says *Dates read as mm/dd/yyyy*, without a chip to switch. A column with values that only fit day first and others that only fit month first stays text. Numbers stored as text (quoted, or with a decimal comma as in `2,50`) are typed as the table is read, when every value of the column (empty ones aside) converts; a column with one other value stays text. This happens before the original version, without a step or a note. A leading zero (`007`, `0612345678`) keeps the column text. Copy and Save on the card take CSV, never the aligned text. The window's meta line says *N rows × M columns*. Where 3 or more column names share a prefix of 10 characters or more up to a separator (` - `, `: `, ` | `, …), the grid and the sidebar show it as *…* (*… PV1 Generation*), per group; Copy and Save keep the real names.
- **No Raw or Original chip**: a text card always shows its formatted view (formatted JSON, XML, YAML, TOML, code, …); there is no chip back to the copy as it came. The chip of the view shown (*Schema*, *To JSON*, a decoder, *Diff*) clicked again goes back to the card's own view. After text recognition a picture card has one toggle, *Show text* / *Show image* (*Toon tekst* / *Toon beeld*), named after where it goes; otherwise its active chip (*Info*, *Text*, *QR*) clicked again shows the picture, and ↶ goes back to v1. The title says *Formatted …* only when formatting changed the text.
- **Table versions**: *Open table* opens the one table window, *Copycraft · Table*. Its toolbar has *Table ▾*, *Copy*, *Save* and the version capsule. *Table ▾* has exactly *Remove duplicate rows* (keeps the first), *Remove empty rows and columns* (trims text first), *Choose columns…*, *Sort ascending ›* and *Sort descending ›* (per column; empty cells last, equal values keep their order). The same steps are in command search on the card (*Undo table step* and *Redo table step* too). Undo and redo are ⌘Z / ⇧⌘Z. A step started from the card shows that version's grid on the card; clicking its chip again goes back to the aligned text. While that grid is showing, the chip row has the version capsule once there is more than one version, and, when a date column fits both orders, a chip *Dates are mm/dd/yyyy* (and back). Reading the table another way starts its versions over from the original, as its columns can change. A step adds a version to the entry instead of a new entry: the original, then one per step, at most 20. The card and the window share that list. The capsule is undo ↶, the version shown (*v2/3*; click it for the list, the one shown checked) and redo ↷, the same size as the history capsule. On the card it sits left of ‹ 1 / 2 ›. On the window it is in the toolbar, with the meta line beside it (rows × columns, labels, the step). The step of the version shown is also in the meta line (*· Duplicates removed*). A step taken from an older version drops the versions after it. Steps run on a background thread (the spinner shows when slow; a newer step cancels the one running). The table is read in the background as soon as the card shows a CSV or TSV, so the menu knows its columns. *Choose columns…* on the window is a dialog: a checkbox per column (the shortened name, the real one in its tooltip), *All* / *None*, and *Apply* or *Cancel*. Apply needs at least one column (otherwise it beeps); with every column still checked it just closes. The same command from the card's search opens a picker over the well: a filter field, a checkbox per column (the shortened name, the real one in its tooltip, the type dimmed), *All* / *None* (on the columns the filter shows; ⌘A is *All*), *Keeping 8 of 20*, and *Apply* (Return) or *Cancel* (Esc). Space ticks the focused checkbox, ↑ ↓ move through the list. *Apply* is off only while no column is kept. *Apply* takes one step, *Kept 8 of 20 columns*, in the table's column order when the set changed; with every column still checked it just closes. *Cancel*, Esc and a click outside the panel dismiss it. The card picker also closes when the app loses focus, on Wipe, lock, retention and when the entry or version changes. Neither picker shows cell values. There is no column overview of sample values: the window's sidebar lists each column's name with its type dimmed beside it, and the toolbar's *Columns* button hides the sidebar. In the grid the first column stays in view while you scroll sideways, as a frozen column in a spreadsheet (from two columns up), in the window and on the card while the card shows the grid: it scrolls up and down with the rows, is drawn from the grid's own text (so it is blurred, masked and wiped with the well) and is left out for VoiceOver, which reads the grid itself. The window shows every row of the version; only tables above 100,000 rows are truncated, with *Showing N of M rows* in the meta. ⌘Z and ⇧⌘Z undo and redo there, ⌘W closes it. Opening another table replaces the window. It opens with the table visible; with the privacy filter on it blurs again when it loses focus (a click reveals it; with it off the table is always shown directly); without a blur filter it stays blank under a hint until revealed; sidebar, grid and frozen column are left out for VoiceOver; it is closed and its text wiped on Wipe, lock, sleep and retention, and whenever its entry leaves the history (*Clear history* leaves a pinned entry's window open) and when the chosen file it shows leaves the card. Copy and Save on the window, and on the card while it shows a table version, take the full version shown: CSV on Copy (the source's separator, `yyyy-mm-dd` dates; the drawn grid is for the screen only), CSV or Parquet on Save. Moving between versions (‹ ›, the capsule, ⌘Z / ⇧⌘Z) only shows them and writes nothing to the clipboard. Its size and sensitivity labels are the version's own. Content you revealed stays revealed in every view, chip, version and step of the entry, also when a step finishes or its labels arrive; another entry, focus loss, Wipe, lock and retention mask it again. Only the steps are kept for every version; the original and the shown table are kept as frames for the entry on the card and those near it, and are worked out again from the copied text when needed. Versions go with their entry (Wipe, lock, retention, and *Clear history* when the entry is not pinned). No new entitlements.
- **Glass and welcome screen**: windows use the Liquid Glass effect (macOS 26); only the welcome screen is opaque navy (the icon's colour, always dark appearance).
- **App icon & Liquid Glass**: the Dock/Finder icon comes from `assets/` via `scripts/build_app_icon.sh` (`icon.icns` today; drop an Icon Composer `AppIcon.icon/` there for the macOS 26 Liquid Glass icon). The accent colour matches the icon's blue: `assets/AccentColor.colorset` (sRGB #6EB4ED, #7DBFF2 in dark mode) is compiled into the same `Assets.car` and `NSAccentColorName` is set, so default buttons, focus rings, checkboxes, CSV headers and the drop outline (`controlAccentColor`) use it while System Settings › Appearance › Accent colour is Multicolour; a chosen system accent still wins. The card, table window, Settings and About use `mac_ui::glass` (NSGlassEffectView on macOS 26+, frosted fallback before); chips and header buttons use Liquid Glass bezels. The menu bar status item stays a template glyph (system tray).
- **Language**: Settings › Language is System (the macOS preferred language), Nederlands or English. Switching applies at once to the card, the table window, Settings, About, the menu bar menu and command search. An open column picker closes. The texts live side by side in `src/locale/strings.rs` (key, Dutch, English); a unit test checks that each key has both and that every key used in the sources exists. Shared panels follow the same choice: OK, Annuleer / Cancel (Escape answers either), Open, Bewaar / Save, and Formaat: / Format:. The save panel's own Cancel button stays the system button. The drop announcement VoiceOver reads is fixed when the card window is first built, for the life of the process. Left in English on purpose: parser messages from the JSON library, polars error messages, search keywords and file names.
- **About**: *About Copycraft* (menu bar and `⋯`) shows the name, the bundle version, a short offline promise, and the GitHub URL as plain selectable text — Copycraft does not open it.
- **Settings**: the menu bar *Settings…* (and the card's `⋯` menu) opens a window for the global hotkey (multi-modifier; Option alone is rejected), the preferred date order (`dd/mm` or `mm/dd` for ambiguous columns), the language (System, Nederlands or English), *Use privacy filter* (*Gebruik privacyfilter*, on by default) and blur on/off for masked content, and *Open at Login* (`SMAppService`, off by default; when macOS needs approval it opens System Settings › Login Items). The privacy filter is the switch for the masking itself: with it on, copied content (text card, picture incl. a Base64 picture, table card and table window, dropped items, Decode views) stays blurred until you click it, as described throughout this README. With it off, all of that is shown directly, unblurred and unmasked, with no click to reveal; the blur checkbox is then dimmed (it only styles the mask), and without a blur filter the blank-under-a-hint fallback applies only while the privacy filter is on. Switching applies live to the open card and the table window, without a restart: switching it on masks what is shown at once (a click reveals it again), switching it off shows it unmasked. The filter does not touch sensitivity labels in the meta line, Wipe, *Clear history*, lock and retention behaviour, *Allow screenshots* (`sharingType none` stays) or concealed-pasteboard handling. Below *Restore defaults* is *Ignored apps*: one line of bundle ids, separated by spaces, commas or semicolons, at most 50. An id is kept only when it is reverse-DNS (it contains a dot, no empty segment, no trailing dot); anything else is dropped, including Copycraft's own id. *Add frontmost app* appends the last other app that was in front and is off when there is none. Copies from those apps are never read. Stored in the standard user defaults. The ignore list is settings only; it never holds clipboard text.
- **Schema / Sample**: JSON → Avro schema (`.avsc`), XML → XSD, XSD → sample XML.
- **Images**: *Info* shows format, size and a data URL. *Text* runs OCR and *QR* reads barcode payloads, both with Apple Vision. After OCR the *Tekst* / *Beeld* toggle (*Show text* / *Show image*) switches between the recognised text and the picture. An SVG (copied, opened or dropped) opens as its picture, with its code as the fallback when it cannot be drawn (or points outside itself).
- **Card actions dock**: the actions of the text well (line numbers, reveal, copy, save, preview) sit in a vertical Dock-style icon column on the well's right edge. It is hidden until the mouse is over that edge.
- **Line numbers**: the numbers button in the dock turns line numbers on or off for plain text cards (off by default, one choice for all cards, in memory). The line count and size stay on the meta line; there is no separate count action.
- **Footer statistics**: the meta line under the preview adds counts: a Markdown card shows its headings (`# ` and `## `, outside code fences), a Java card its methods by access level (public, protected, private and package, constructors left out).
- **Image versions**: the *Image ▾* chip (on a copied picture in history and on a dropped or chosen one) has *Resize* ▸ *50%*, *25%*, *Longest side 2048 / 1024 / 512* and *Custom…* (a width, `1200` or `w 1200`, or a height, `h 800`), then *Rotate 90° left / right*, *Flip horizontal / vertical*, *Remove metadata* and *Grayscale*, and *Undo image step* / *Redo image step*; they are in the command search too. Resize keeps the proportions and never makes a picture larger: a size it already fits says "Already that size or smaller" in the meta line and makes no version. The picture is read upright (its EXIF orientation applied) with ImageIO, and every version is a PNG without metadata (no EXIF, GPS or camera data); *Remove metadata* makes such a copy without changing a pixel. Each step is a version of the entry, as for a table: the original, then one per step, at most 20, with the same version capsule (*v2/3*, undo ↶, redo ↷, ⌘Z and ⇧⌘Z) in the picture view and the step in the meta line with the version's size (*PNG  1024×768  0.21 MB  ·  Resized to 1024×768*). Only the steps are kept for every version; a version is worked out from the original by replaying them, on a background thread (the spinner shows when slow; a newer step cancels the one running), and the one shown and the two shown before it are kept as pictures, zeroized when they are dropped and with their entry (Wipe, lock, retention, and *Clear history* when the entry is not pinned). *Info*, *Text* and *QR* read the version shown (scanned once it is there, and kept with it). *Copy* puts the version shown on the pasteboard as PNG data (`public.png`) and into history as a new copy. *Save* has a *Format* popup under the panel: *PNG*, *JPEG — high (0.9)*, *JPEG — medium (0.7)* and *HEIC*, all written upright without metadata, and for the original also the original *as it is* (byte for byte, metadata included), which is picked first; for a step's version the source's format is picked first (JPEG, HEIC, else PNG). Switching it switches the name's one extension. The picture stays revealed through its versions.
- **Lines…**: on every text and code card, including an opened or dropped file (not on a table, a link or a picture), the *Lines…* chip (*Regels…*; formerly *Text…*) has Unix-style line tools, worked out in Rust (no subprocess). Line count and size stay on the meta line under the preview. *First lines…* and *Last lines…* (`head`/`tail`; a prompt asks for N, 10 to start), *Reverse lines* (`tac`) and *Column…* (`awk '{print $N}'`; the separator is detected (tab, comma, semicolon, pipe, else runs of whitespace) and can be changed in a pop-up, the column starts at 1, a live preview shows the first lines, and lines without that column are skipped), and *Filter (regex)…* (`grep`, with *Invert* (`grep -v`) and *Ignore case* (`grep -i`); a live preview shows how many lines match and the first of them with the matches highlighted; an invalid pattern is shown in red instead, never an error dialog; patterns are compiled with size limits and match in linear time). Line endings (LF or CRLF) and a final newline stay as copied. Each step copies its result (concealed when it is sensitive, like *Copy*) and so becomes the newest history entry; the versions are those entries, with the same version capsule as a table (*v2/3*, undo ↶, redo ↷, ⌘Z and ⇧⌘Z), which only shows the version: the clipboard is left alone and there is no *Copied* toast; *Copy* puts the version shown on the clipboard. Nothing else is stored: only the entries' ids and the step names, forgotten with *Wipe*. A step that would leave nothing says so in the meta line and makes no version. All this work (the steps, the filter and the live previews of *Column…* and *Filter…*) runs on a background thread, like the card itself: only the result comes back to the main thread, which updates the card and the clipboard, and a result that is stale by then (a newer step or keystroke, another entry, Wipe) is dropped.
- **PDF**: a PDF dropped on the card or chosen with *Kies bestand* shows the PDF itself: its first page, drawn in memory with CoreGraphics, as an image card with the same *Tekst* / *Beeld* toggle, *Info* and image versions as any picture. *Beeld* (the PDF) is the default; *Tekst* shows the text of its first 100 pages, read with PDFKit on the background worker (PDFKit is touched on the main thread only, through `run_on_main`), with the page count first in the footer (*12 pagina's*, or *Eerste 100 van 340 pagina's*) followed by the usual text stats. Only the first page is drawn: there is no scrolling through pages yet. The *AI* chip works on that text (cut at 20,000 characters, with the notice), with the usual preview and *Toepassen op klembord*. A PDF with a password is refused with a note. A PDF without a text layer (a scan) gets its first 10 pages recognised with Apple Vision after the card is up; until that is done the *AI* chip is dimmed (*Wacht tot de tekst in de PDF is herkend*), and also when no text is found (*In deze PDF is geen tekst herkend*). A PDF copied in Finder (*Copy*, then the hotkey) has no such card: it shows its text, and a scan is not read; drop it instead. Nothing is written to disk or cached, nothing is logged, and the bytes, text and rendered pages are zeroized like other cards (PDFKit and Foundation keep their own copies while a read runs; those are released when it ends).
- **Apple Intelligence**: the *AI* chip (✨ `sparkles`, left of *Lines…*; dimmed with the reason as tooltip when unavailable) offers only what fits the card, at most four entries: **prose** (text, plain, Markdown, and the recognized text of a scanned PDF): *Summarize*, *Rewrite* ▸ *Shorter* / *More formal*, *Fix spelling and grammar* and *Translate NL↔EN* (*Samenvatten*, *Herschrijven* ▸ *Korter* / *Formeler*, *Spelling en grammatica*, *Vertalen NL↔EN*); **code** (Rust, Java, Python): *Explain what it does* and *Suggest a doc comment* (*Uitleggen wat het doet*, *Commentaarregel voorstellen*); **JSON and YAML**: *Explain the structure* (*Structuur uitleggen*); **agent instructions** (AGENTS.md and the like): *Summarize* and *Unclear points and conflicts* (*Onduidelijkheden en conflicten*). Links, XML, HTML, SVG, TOML, tables (CSV, TSV, the table window) and pictures have no AI chip and no actions (logs, regular expressions and shell commands are not recognized as card types, so they get the prose menu as plain text); each has one short, concrete instruction for the model (one task, same language as the text, no added facts) and the card text is sent as data in its own delimited section (markers inside the text are defused), the model has no tools, files or commands and nothing is logged or stored. The text goes to the model whole, by pointer and byte length (not cut, not NUL-terminated; only the 20,000-character limit below applies), at a low temperature, run by the on-device Apple Foundation Models (crate `mac-ai`: a small Swift bridge, compiled by `build.rs` with `swiftc` and linked into the binary; all `unsafe` of the feature is in that crate). Nothing runs on its own: only a click on one of these items. They need macOS 26, Apple silicon and Apple Intelligence switched on in System Settings; otherwise they are dimmed and say why (tooltip and a last dimmed line). The work runs on a background thread; the result is a preview over the card with *Cancel* (Esc, also stops the model) and *Apply to clipboard* (*Toepassen op klembord*, Return), which makes it a new Lines… version like any other step (⌘Z goes back). Until then nothing is on the clipboard or in history, and closing the preview, the card or Wipe drops the result. The preview has a *Hide* (*Verberg*) button: the card goes to the background and the run and preview stay; while it is hidden the menu bar icon shows … (running) and then ✓ (result ready, also read out by VoiceOver), and a click on the icon (or the hotkey) brings the card back with the run or preview intact. The icon and the hotkey hide the card as usual, and with a run or preview that does not end it (also on a PDF card): the next click shows the same card again (not a new card for a newer copy) with the run or result intact. Only *Cancel*, Esc or *Apply* end it. Text over 20,000 characters is cut, with a notice. Table cards (CSV, TSV and the like) and the table window have no AI chip or actions. At launch Copycraft checks in the background whether Apple Intelligence works; when it does not it shows one warning per session (a Dutch or English alert) with the reason and what to do: macOS before 26, no Apple silicon, an unsupported Mac, Apple Intelligence switched off (*Zet Apple Intelligence aan in Systeeminstellingen*), the model still downloading or preparing, a build made without `swiftc` (no Swift bridge), or an unknown status. The *AI* chip shows the same reason as its tooltip while dimmed, and *⋯ › Controleer AI* (*Check AI*) asks again and shows the result, also when everything works; only the status is involved, nothing about your content. The model runs on the Mac: no network and no extra entitlement; text, prompts and results are never logged (a failure logs only its kind) and nothing is cached on disk.
- **Background work**: the card (detection, sensitivity aside, and every format: JSON, XML, Markdown, code, HTML, the dataframe views), the table window's grid, the conversion behind *Copy* (and the table window's Copy), and reading a dropped or chosen file run on a background thread. The main thread waits at most 30 ms, so a quick result looks exactly as before; a slower card shows *Working…* (the spinner after a moment) and is replaced when it is ready, if the card still shows that item and view. Each kind of job has a sequence number: a result overtaken by a newer job is dropped. Only AppKit and the clipboard write stay on the main thread. Table steps, image steps, saves, the diff and Lines… already ran in the background.
- **Look and motion**: one set of spacing, corner, type and timing constants (`mac_ui::style`) for the card, footer, Settings, About and the toast. Windows sit on Liquid Glass (macOS 26), vibrancy before that, and an opaque background with Reduce Transparency. The card fades in (150 ms) and out (100 ms); its window never moves or resizes for that, and a "Working…" placeholder keeps the size of the card before it; a new page or filter preview crossfades (120 ms). Reduce Motion keeps the fades. After a copy a small toast with a green check says *Gekopieerd* / *Copied* for about 1.2 s; VoiceOver announces it at normal priority unless Settings › *Announce confirmations* (*Bevestigingen voorlezen*) is off, which keeps the toast. *Wis* / *Clear* on the card first asks *Wissen?* / *Clear?* (*Annuleer* is the default and answers Esc); *Niet meer vragen* / *Don't ask again* turns that off, and Settings › *Ask before clearing* turns it back on. Turning Reduce Transparency or Increase Contrast on or off restyles the open card, Settings, About and the toast at once, without a relaunch. At most four chips show on the card (*Lines…* always); the rest are under `⋯`. Chips and menu items carry SF Symbols; code and tables use SF Mono.
- **Paged long text**: with Settings › *Show long text in pages* on (the default), *Show all* on a text of more than 200 lines shows it one page at a time, like `more`: Space is the next page, b the previous, g and G the first and last, Esc or q shows the whole text again. The last line of the well says *--More-- page 3 of 12 (25%)*. The pages follow the card's height; after a resize the first line shown stays in view. The line index is worked out on the show-all thread, so paging only slices the text. A filtered result is a new entry and pages the same way.
- **Links**: when the clipboard (a drop or a history entry) is one `http`/`https` link and nothing else, the card is titled *Link* (*YouTube* for a video) and shows the URL as plain text, selectable; *Copy* copies it. Nothing is fetched: no page title, preview image or thumbnail. *Visit* opens only `http`/`https` links in your default browser (through `NSWorkspace`), with `user:password@` stripped; the browser loads the page, not Copycraft.
- **Copy / Save**: copy the current view back to the clipboard, or save it through a save panel. The file extension follows the content; the suggested name is the chosen or dropped file's name without its own extension (*people.tsv* → *people.csv*), else *clipboard*, with that one extension.
- **Choose file**: show a local text file (up to 8 MB) on the card instead of the clipboard. A chosen or dropped file (a PDF too) is the card's last content: hiding the card (icon, hotkey, Esc) keeps it, and the next click shows the same card again, with its versions. It gives way only when new clipboard content comes in from another app (or *Clipboard* in `⋯`).
- **Drop**: drop one text file or text (up to 8 MB), one picture (up to 32 MB) or one PDF (up to 32 MB, see *PDF*), on the card to show it the same way. A picture can be an image file from Finder (PNG, JPEG, HEIC, GIF, WebP, TIFF, BMP, … anything macOS can draw), an image dragged from Safari or Preview, or a photo from Photos (a promised file, written to a temporary folder that is deleted once read). It gets the image card with *Info*, *Text* and *QR*, blurred like a copied image, and *Save* writes it in its own format (or PNG, JPEG or HEIC, see *Image versions*). A drop goes into history like a copy, without changing the clipboard. Several files, folders and other files are refused. The card stays open while you work in another app, so open it, then drag from Finder, Safari, Preview, Photos or Notes onto it.
- **History**: the last 20 unpinned copies and drops (text and images), plus up to 20 pins, kept in memory only (a text over 5 MB or a picture over 20 MB is not kept; over 200 MB in all, the oldest unpinned entries go first), and by default forgotten 15 minutes after the last copy (*Keep history 5 / 15 / 60 min after the last copy* or *until cleared* in `⋯`, stored in the user defaults). Whatever that setting, history is always forgotten when the screen locks, the Mac goes to sleep (or its displays do) or you switch to another user, pins included. A pin skips both the 20-copy cap and the 5 / 15 / 60 minute timer. *Clear history* forgets only unpinned copies and leaves pins. *Clear pins* forgets only pins. *Remove from history* deletes the entry on screen. *Wipe*, quit, lock, sleep and switching user forget pins as well as everything else. A pinned row is marked with *•* in front of its type and size in the card's *History* list and in the menu bar *History* submenu; that mark is not part of the copied text, and those rows never show the copied sentence. Copying a pinned item again moves it to the front and keeps the pin, its id and its cards. Copying the newest entry again changes nothing. Copying an older unpinned item again replaces it with a new entry. A 21st pin does nothing and the meta line says the pin list is full. Step through them with the ‹ / › chevrons in the glass capsule at the right of the chip row, which shows where you are (*1 / 5*; 1 is the newest copy, as in the *History* submenu; › *Next* counts up to older copies, ‹ *Previous* counts back down toward 1), with ← / → (or ⌘← / ⌘→, see *Usage*), or use the menu bar *History* submenu. The capsule appears once history holds two copies. Each copy's format is worked out once. Its card, and a picture's scan (info, recognized text, QR payload), are kept with the history entry while it is shown or next to the one shown, so stepping back and forth does not redo them; further away they are zeroized and worked out again when needed, and they never outlive the entry (an unpinned entry falling off the end, *Remove from history*, *Clear history*, *Clear pins*, *Wipe*, lock, sleep or switching user). A history picture goes back on the pasteboard as data in its own type (JPEG stays JPEG) plus a PNG copy for apps that only paste PNG (TIFF if that conversion fails), never as a temporary file; files an older version left in the temporary folder (`copycraft-history-*`) are removed at launch. Stepping through history (‹ ›, ← / →, ⌘← / ⌘→ from search) only shows the entry: nothing is written to the clipboard and there is no *Copied* toast. The card keeps showing that entry through polls and background refreshes until another app copies something new; *Copy* puts the entry shown on the clipboard as the newest copy. Opening the card again starts at the clipboard's item. Everything Copycraft writes to the pasteboard carries its own type `nl.marcelkoopman.copycraft.self`, so its own writes are not taken for a new copy; *Copy*, *Format* on a link and a history entry chosen from the menu are recorded as the newest copy when they are written.
- **Diff**: compare two text copies. In `⋯` › *History* each text row says *Add to diff*, then *Compare with A* once one is chosen, and *Remove from diff* while it is chosen. A chosen row is marked *A* or *B* in front of its type and size. The copy on screen has the same action on `⋯` itself, and *Swap* appears there once two are chosen (A on the left, B on the right). A third pick replaces the oldest. Pictures stay disabled. Command search has the same actions. The card then shows a *Diff* chip. The well is A on the left and B on the right; a run of unchanged lines folds to *···*. The meta line says *+N / −M lines*, or *No differences*. JSON objects and arrays are compared after pretty-printing with sorted keys, so key order alone is not a difference; when that leaves them equal, the well still shows each copy as it was. A side over 1 MB or 20,000 lines says *Too large to compare*. While it runs the well says *Comparing…*. Copy and Save take the unified `+` / `-` lines (or *No differences* / *Too large to compare*). The comparison is not a history entry. It stays until Wipe, lock or a cleared history, is masked like other content, and carries the labels of both sides. Nothing is stored on disk.

## Decoders

Text that decodes gets exactly one extra chip, named after what it is. When several fit, the first of JWT > UUID > Unix time > URL > Hash > Base64 wins. The chip is tried on plain text, prose and links, and on any copy that is a single token without white space. Detection is string work only (no network, no new rights) and runs with the other chips, off the main thread for a large copy. The decoded view is blurred until clicked and keeps the copy's sensitivity labels (a decoded JWT still says *credential*), plus any labels of what decoding reveals. Labels in the view follow Settings › Language (System, Nederlands or English).

- **JWT** (`header.payload.signature`, header JSON with `alg`): *Signature not verified* / *Handtekening niet gecontroleerd* first (the signature is never checked), then `iat`, `nbf` and `exp` as dates in local time and UTC (Settings date order) with a status: *expired (4 days ago)* / *verlopen (4 dagen geleden)*, *valid for 30 minutes* / *nog 30 minuten geldig* (minutes up to two hours, then hours, days, years), *not valid yet (in 2 hours)* / *nog niet geldig (over 2 uur)*; then header and payload as pretty JSON in the JSON card's colors.
- **UUID**: canonical `8-4-4-4-12` hex, also in braces (`{…}`) or after `urn:uuid:`: the lowercase form, version (*Version 4 (random)* / *Versie 4 (willekeurig)*, …) and variant (RFC 9562, NCS, Microsoft, reserved; nil and max UUIDs are named). Version 1 (100 ns since 1582-10-15) and version 7 (Unix milliseconds) also show their timestamp in local time and UTC, and how long ago. 32 hex digits without dashes are not taken for a UUID. A braced GUID also reads as a YAML flow mapping, so it keeps its *To JSON* chip next to *UUID*.
- **Unix time** / **Unix-tijd**: a bare integer of 10 digits (seconds) or 13 digits (milliseconds) from 2001-09-09 up to 2100: the date in local time (with its offset) and UTC in the Settings date order (`dd/mm/yyyy` or `mm/dd/yyyy`, as for tables), relative (*3 days ago* / *3 dagen geleden*, *in 5 minutes* / *over 5 minuten*), and ISO 8601 UTC. Phone-like numbers (`06…`) and other lengths are left alone.
- **URL**: offered when the copy has `%xx` escapes or is a full URL with a query. A URL is shown in parts: scheme, host (with port), path, then the query parameters one `key = value` per line, each decoded (`%xx`, and `+` as a space in the query), then the fragment; `user:password@` is left out. A URL encoded as a whole (`https%3A%2F%2F…`) shows the decoded URL and then its parts; other text shows decoded. A page link with a query gets *URL* after *Visit* (*Visit* stays first); a YouTube video link does not.
- **Hash**: hex digits of one case, with letters and digits, recognised by length only: 32 *Probably MD5* / *Waarschijnlijk MD5* (or a UUID without dashes), 40 SHA-1, 56 SHA-224, 64 SHA-256, 96 SHA-384, 128 SHA-512. Never reversed or looked up. Copycraft does not compute hashes or encode Base64.
- **Base64**: Base64 and Base64URL, with or without padding, and `data:…;base64,` URIs. Only offered when the bytes are readable UTF-8 text (shown as is), JSON (shown pretty) or a picture: PNG, JPEG, GIF, WebP or HEIC is recognised by its magic bytes and described as type, size in pixels (read from the header) and byte count, and the picture itself is drawn in the card's well. It is decoded on a background thread (the card describes it until the picture arrives) and drawn the way a dropped picture is, blurred until clicked like any picture; the description stays on the meta line, with the labels of the copy. Its chip clicked again goes back to the text. A picture over 20 MB decoded, or over 50 megapixels where the header says, or one the system cannot read, is not drawn: the description stays (with *Not shown: larger than 20 MB* / *Niet getoond: groter dan 20 MB*). Copy and Save in this view still take the description text. Ordinary words (*hello*, *Test*, *password*) are not Base64: at least 8 characters, one alphabet, padding only where the length needs it, and decoded text must read as text.

## Privacy

- **Offline by design**: Copycraft never goes online. It makes no network connections and has no networking code or libraries of its own, and the signed app has no network entitlement (only `com.apple.security.app-sandbox` and `com.apple.security.files.user-selected.read-write`), so the App Sandbox refuses a connection as well. Text recognition and barcode reading (Apple Vision) and the blur (CoreImage) run on the device. *Visit* hands a link to your browser. CI checks this: `scripts/check_copycraft_offline.sh` fails when Copycraft's dependency tree holds an HTTP, TLS or socket crate (one exception: `socket2`, which polars' tokio runtime always pulls in and Copycraft never uses) or its sources mention `osascript`, and `apps/copycraft/clippy.toml` makes clippy refuse `std::process::Command`, `std::net` and `std::os::unix::net`.
- **No other rights**: besides the sandbox and files you pick, the signed app has no entitlements: no hardened-runtime exceptions (`com.apple.security.cs.*`) and no Apple Events. *Choose file* and *Save* use the native open and save panels in the app itself (`NSOpenPanel`, `NSSavePanel`), never `osascript`. A test pins the entitlements file, and `scripts/sign_app.sh` and the release workflow check the signed app.
- **Masked content**: the card blurs copied content until you click it. The blur is light enough to recognise the shape (lines, indentation, a picture's outline) but keeps text unreadable; pictures get a stronger blur than text, since text in a picture can be large.
- **Sensitivity labels**: the meta line flags **credential**, **PII** and **financial** content. A first layer of Copycraft's own recognizers runs in one linear regex pass with validation afterwards: private-key headers, JWTs, AWS/GitHub/Slack/Stripe/Google/OpenAI/GitLab/npm tokens, IBAN (mod-97), cards (Luhn), email, NL mobile numbers (on one line, not the tail of a decimal such as `10.06`), BSN (elfproef), and labeled or tabular fields such as names and salaries. [leakguard](https://crates.io/crates/leakguard) then looks only for the classes not found yet (URL credentials, Azure/Telegram/Discord tokens, IP and MAC addresses, US SSNs). Both are linear: about 60 ms for a megabyte. Copycraft only labels content. It never rewrites it. Copies from 32 KB up are checked on a background thread: the card opens right away, its meta line says *Checking…* until the labels arrive, and the content cannot be revealed before that (the click beeps). A newer copy cancels a check that is still running. In documentation (Markdown and agent-instruction files) an e-mail address counts as PII only from three different addresses (a contact list): a README with one or two support or author addresses is not flagged, while a phone number, BSN, IBAN, card, labeled field or key in the same text still is. Anywhere else a single e-mail address is PII, on purpose: a copied address is nearly always a person's.
- **Private copies**: a copy another app marks private with the [nspasteboard.org](http://nspasteboard.org) types (`org.nspasteboard.ConcealedType` from a password manager, `TransientType`, `AutoGeneratedType`) is never recorded in history and its text is not read: the card only says *Hidden content*. When Copycraft itself puts text labelled *credential*, *PII* or *financial* on the pasteboard (*Copy*, a history step), it adds `ConcealedType`, so other clipboard managers skip it, and by default it empties the pasteboard again 60 seconds later if nothing else was copied meanwhile (*Clear sensitive copies after 60 s* in `⋯`, stored in the user defaults).
- **Polling**: macOS has no notification for clipboard changes, so Copycraft looks at the pasteboard's change count every 3 seconds while the card is closed and every 400 ms while it is open; the frontmost app is only asked when the count changed. Only when the count changes is the copy read, hashed and recorded, unless recording is paused, this is the ignored next copy, or the frontmost app is on the ignore list. Copying the newest entry again changes nothing in history. Pasteboard privacy (macOS 15.4+, see `docs/pasteboard-privacy/FINDINGS.md`): the access setting (*Privacy & Security › Paste from Other Apps*) picks how copies are read, and is looked at again on every look at a new copy and whenever the card opens, so a change in Settings is picked up while Copycraft runs (and logged). *Allow* (and macOS before 15.4): every copy is read as it comes, as above. *Ask* (or never asked yet): while the card is closed Copycraft only watches the change count and the types (no alert); the menu bar tooltip says *New copy — open the card to view*, and the copy is read when you open the card, in one pass on the main thread that history, the card, the picture and its scan share, so macOS asks at most once per copy. Copies you never open are not read, so they are not in history. The first time, the card first explains the alert (once): choose *Allow* to see the copy, or set Copycraft to *Always Allow* in Settings. *Deny*: Copycraft reads no contents at all (only the change count and the types) and the card says *Clipboard access denied in Privacy & Security*. A reading that comes back empty, fails or is denied is not tried again until another copy or other types, and the pasteboard is only read on the main thread (the image scan decodes on its own thread what was fetched before).
- **Pause and ignore-next**: *Pause recording* and *Ignore next copy* live in the menu bar menu (both with a check mark), in `⋯` and in command search. They are session flags: off at every start, and not stored in the user defaults. Pause survives lock, sleep and a user switch; ignore-next stays armed too. While paused, a new copy from another app is not read and the menu bar says *Paused*. An ignored copy, while recording is not paused, says *Copy ignored*. Ignore-next skips one such copy, then turns off. A skipped copy stays unread after you resume or unlock, until a newer copy. Concealed, transient and auto-generated copies stay *Hidden content* and do not use up ignore-next. Copycraft's own writes (*Copy*, a history step) are always read. Pause does not use up ignore-next.
- **Ignored apps**: a copy is never read when the frontmost app's bundle id is on the ignore list (Settings, at most 50). The source app is whoever is frontmost when the poller sees a new change count, so it can be the wrong app if you switch inside the poll interval (3 s with the card closed, 400 ms while it is open). macOS has no public pasteboard-writer API. The list applies on the next poll. Copies already in history stay. Removing an app does not read what was skipped. *Add frontmost app* and *Ignore copies from the frontmost app* append the last other app that was frontmost; the Settings window itself is not added.
- **Search**: typing on the card searches actions and the text already held in history, case-insensitive, up to the first 64 KB of each entry. A match only past 64 KB is missed. With the privacy filter on, a history hit is titled with its type and size (and *•* when pinned). With the filter off, the title is one line of the text, trimmed and cut at about 80 characters; a match outside that line still hits. Images do not match their pixels or their recognized text. The menu bar *History* submenu and the `⋯` history rows stay type and size and never show the copied text.
- **Wipe**: the *Wipe* button clears history, pins included, plus caches, the card and the pasteboard. Copied text and image buffers are zeroized when they are dropped (`zeroize`). Beyond that, Copycraft's own allocator overwrites every block of heap memory with zeros before it is freed, so copies that libraries make on the way (Polars' table columns and the CSV reader's chunks, rendered grids, hash tables) do not linger in freed memory either.
- **Masked again on focus loss**: the card stays open (floating) when another app becomes active, but content you revealed is blurred again. It closes with ✕, Esc, the hotkey or a click on the menu bar icon.
- **Out of screen capture**: the card and the table window ask macOS to leave them out of screenshots, screen recordings and screen sharing (`NSWindowSharingNone`). That is a request, not a guarantee: Apple documents the setting as a legacy constant not to be used to hide content from capture ([NSWindow.SharingType.none](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none)), and ScreenCaptureKit on macOS 15.4+ is reported to capture such windows anyway; Apple says there is no public API to prevent screen capture ([Developer Forums 792152](https://developer.apple.com/forums/thread/792152)). The blur stays the protection. For testing, *Allow screenshots* in the menu bar menu (with a checkmark) lets screenshots, recordings and screen sharing capture the card and the table window (read-only sharing) until it is switched off; it is off at every start and never stored. Blur and wipe work the same either way.

## Code complexity

On a Rust, Java or Python card, *Lines… › Complexity* (*Regels… › Complexiteit*) lists every
function or method with its line range and cognitive complexity, highest first, with the
total and average below. 16–25 is shown in orange and marked *high*, above 25 in red and
marked *very high*. Click a row to scroll the card to that function. The scores are worked
out in the background and are an approximation of SonarQube's cognitive complexity (one
lexical pass, no parser): `if`, `else if`/`elif`, `else`, ternaries, `switch`/`match`, loops,
`catch`/`except`, labelled `break`/`continue`, mixed `&&`/`||` (`and`/`or`) sequences and
direct recursion count; nested structures, lambdas and closures add one per level. Only
counts and timings are logged, never code. Texts over 512 KB or 20,000 lines are not scanned and show
*Too large for complexity analysis* instead.

## Agent instructions

`AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `.cursor/rules/*.mdc`, `copilot-instructions.md`
and `GEMINI.md` opened with *Choose file* get the *Agent instructions* card
(*Agent-instructies*). Pasted text gets it only when it clearly reads as instructions:
Markdown with several typical headings (Build, Test, Setup, Code style, Conventions,
Commands, PR instructions) and a shell code block. A README stays Markdown. The footer shows
a rough token estimate (characters / 4). *Lines…* then offers:

- *Commands* (*Commando's*): the lines of shell/bash/sh/console blocks and inline commands
  in lists (cargo, npm, pnpm, yarn, make, pytest, go, git, gradle, mvn), in order, each
  once, as a new version on the clipboard (⌘Z goes back for a copied text; an opened file
  is left for the clipboard).
- *Outline* (*Overzicht*): the headings; pick one to scroll the card there.
- *Check* (*Controle*): possible secrets (line and kind only, never the value), a very long
  file (over 500 lines or about 8k tokens), empty sections, duplicate headings, in-file
  `#anchor` links that match no heading (links to other files are not checked) and a missing
  Build or Test section. A section counts only when its heading is exactly a known name
  (case-insensitive, trailing `:` ignored), such as *Build* or *Testing*.

Only counts are logged, never the instructions.

## Logs and diagnostics

Copycraft logs events only: what happened, counts, sizes, types and error kinds. It never
logs clipboard or history text, file contents, file names or paths, decoder input or output,
regex patterns or table data.

**View the log in Console.** Open Console.app, select your Mac, click Start streaming and
search for `subsystem:com.github.marcelkoopman.mac-apps.copycraft`. The categories are
`clipboard`, `table`, `decode`, `settings`, `window`, `login` and `worker`. Include Info and
Debug messages (Action > Include Info Messages / Include Debug Messages) to see everything.

**Export diagnostics.** In the `⋯` menu choose *Export diagnostics…* (*Diagnose
exporteren…*) and save the `.txt` file. It holds the app version, the macOS version, the
settings (values only) and the log lines of the last 24 hours of the current run, kept in
memory. Attach it to your support request.

## Build and run

From the repo root:

Needs macOS 26 and Xcode 26 (the Swift bridge of the Apple Intelligence actions is compiled by
`crates/mac-ai/build.rs` with `swiftc`; without `swiftc`, or on another OS, the app builds and
reports the actions as unavailable). The binary also says macOS 26 as its minimum: `.cargo/config.toml` sets
`MACOSX_DEPLOYMENT_TARGET=26.0` for every cargo build.

```bash
cargo run -p copycraft
cargo test -p copycraft
cargo clippy -p copycraft --all-targets -- -D warnings
```

Test data: [`testdata/`](testdata/README.md) has a synthetic input for every scenario
(detection, convert and decode, tables, diffs, sensitivity labels, edge cases, images) with a manifest
of what the card should show. `cargo test -p copycraft testdata_manifest` checks the manifest
against the app; `testdata/generate_large.sh` writes the 1 MB and over-8 MB files.

Local app bundle (needs `cargo-bundle`):

```bash
cd apps/copycraft && cargo bundle --release
```

## App Store readiness

Preparation only: Copycraft is not submitted to the Mac App Store, and none of this was run through App Store review. What is in the repo:

- **Bundle identifier**: `com.github.marcelkoopman.mac-apps.copycraft` (`identifier` in `[package.metadata.bundle]`, and `OWN_BUNDLE` in `src/capture.rs`, which must match). It replaced the earlier id without the `mac-apps.` segment before the first Store submission. A new bundle id means a new sandbox container (`~/Library/Containers/<id>/`) and a new defaults domain, so a copy that was installed under the old id starts from the defaults once (language, privacy filter, hotkey, date order, ignored apps) and macOS asks again for *Paste from Other Apps* and for Open at Login. There is no migration code; nothing was released under the old id to migrate. `scripts/check_copycraft_offline.sh` fails when the old id is still in the repo.
- **Privacy manifest**: `apps/copycraft/PrivacyInfo.xcprivacy`, shipped as `Contents/Resources/PrivacyInfo.xcprivacy` through `resources` in `[package.metadata.bundle]`. It declares no tracking, no tracking domains and no collected data (Copycraft is offline). Required-reason APIs, from reading the sources and the dependencies:
  - `UserDefaults` **CA92.1**: the app's own settings and appearance, in its own defaults domain (`src/settings.rs`, `mac_ui::theme`).
  - `FileTimestamp` **C617.1**: `std::fs::metadata` (stat) on its own files in the app container (preview files in the temporary directory). **3B52.1**: stat on files you picked with the open panel, dropped on the card or copied from Finder (`src/open_file.rs`, `src/macos_pasteboard.rs`).
  - `SystemBootTime` **35F9.1**: `std::time::Instant` (the monotonic uptime clock on macOS) for elapsed time between events inside the app.
  - Not declared: disk space (no statvfs or volume-capacity calls in Copycraft; `sysinfo` is in the tree through polars but without its disk feature) and active keyboard APIs (Apple lists the UIKit call; winit's keyboard-layout lookup is not on the list).
  - These are my reading, not an Apple verdict; App Store Connect reports missing declarations on upload.
- **Export compliance**: `ITSAppUsesNonExemptEncryption` is `false` in `assets/Info.plist.ext`. Copycraft has no network code and no encryption of its own; the dependency tree holds hashing for deduplication (std `DefaultHasher`, not cryptographic) and `rand` with `chacha20` as a random number generator (via polars), not used to encrypt anything. `scripts/check_copycraft_offline.sh` keeps TLS and HTTP crates out. The declaration to Apple is the owner's to make; check it before upload.
- **Checks**: `apps/copycraft/tests/privacy_manifest.rs` (runs everywhere); `scripts/check_privacy_manifest.sh` (macOS: `plutil -lint`, the file is in the bundle, the export key is in `Info.plist`), called by `scripts/sign_app.sh`, the release workflow (before and after signing) and CI (source file). To check by hand on a built app: `plutil -lint Copycraft.app/Contents/Resources/PrivacyInfo.xcprivacy` and `plutil -p Copycraft.app/Contents/Info.plist | grep ITSApps`.

Still missing for the Store: distribution signing (an Apple Distribution and a Mac Installer Distribution certificate; releases are ad-hoc signed or Developer ID, which the Store does not take), a provisioning profile embedded in the app (`embedded.provisionprofile`) and the application and team identifier entitlements, a signed `.pkg` for upload, and the App Store Connect record: description, screenshots, category, age rating, privacy answers (these must match the manifest) and review notes. The sandbox entitlements already exist; whether they suffice for review (for example the global hotkey and pasteboard polling) has not been tested.
